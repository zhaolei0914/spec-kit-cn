## /0-制定项目上下文

自动分析项目代码，生成项目上下文和开发规范 SKILL 文件。

### 用法

```
/0-制定项目上下文
```

### 执行流程

#### 阶段 1：自动生成 Skill 文件

根据项目类型选择分析工具：

- **Shell 脚本项目**：使用语言专用脚本
  ```bash
  python .specify/scripts/shell/skill_main.py all . --output .specify/skills/project-context
  ```

- **Python 项目**：使用 Python 专用脚本
  ```bash
  python .specify/scripts/python/skill_main.py all . --output .specify/skills/project-context
  ```

- **其他项目**：使用 GitNexus 知识图谱分析（需 Docker）
  ```bash
  bash .specify/scripts/docker/gitnexus/gitnexus.sh analyze --skills .
  python .specify/scripts/docker/gitnexus/gitnexus_to_skill.py . --output .specify/skills/project-context
  ```

#### 阶段 2：LLM 推理填充

读取生成的 `SKILL.md` 和 `.context-facts.json`，填充所有 `{{LLM_*}}` 占位符：

1. **项目概述**：`{{LLM_PROJECT_SUMMARY}}`、`{{LLM_ARCHITECTURE}}`
2. **技术栈**：`{{LLM_FRAMEWORKS}}`、`{{LLM_MIDDLEWARE}}`、`{{LLM_VERSIONS}}`
3. **业务逻辑**：`{{LLM_BUSINESS_FLOWS}}`、`{{LLM_DESIGN_PATTERNS}}`
4. **规范类**：`{{LLM_NAMING_CONVENTIONS}}`、`{{LLM_CODE_STYLE}}`、`{{LLM_FORBIDDEN_RULES}}`
5. **环境部署**：`{{LLM_DEPLOYMENT}}`、`{{LLM_ENV_VARIABLES}}`

**质量自检**：
- 确认无残留 `{{LLM_` 占位符
- 检查事实一致性，无虚构路径
- SKILL.md 控制在 300-500 行

#### 阶段 3：验证 Skill 文件

- [ ] Skill 文件已生成：`.specify/skills/project-context/`
- [ ] 所有占位符已替换
- [ ] 无虚构文件路径、类名或函数名
- [ ] 项目概述准确

#### 阶段 4：创建归档目录

```bash
mkdir -p specs/archived/
```

#### 阶段 5：追加项目记忆引用

在 `SKILL.md` 末尾追加文档模板和项目记忆引用章节。

#### 阶段 6：更新项目规则

1. **检测项目实际情况**：确定代码目录、specs 目录
2. **确保 AGENT_RULES_FILE 存在**：不存在则创建
3. **读取模板**：从 `.specify/templates/AGENT_RULES_FILE.md` 读取
4. **填充变量**：替换 `{{CODE_DIRS}}`、`{{SPECS_DIR}}` 等占位符
5. **追加内容**：写入 `CLAUDE.md` 或对应代理规则文件

#### 阶段 7：创建变更日志文件

确保 `.ai-changelogs.md` 存在：

```markdown
# 变更日志

## 未同步
（当前无未同步变更）

## 已同步

## 归档
```

### 前置条件

- 项目代码已存在于当前工作区
- 有读写 `.specify/` 目录的权限

### 输出产物

| 文件 | 说明 |
|------|------|
| `.specify/skills/project-context/SKILL.md` | 项目上下文和开发规范 |
| `.specify/skills/project-context/.context-facts.json` | 采集的事实数据 |
| `specs/archived/` | 归档目录 |
| `CLAUDE.md` (或对应代理规则文件) | 更新的项目规则 |
| `.ai-changelogs.md` | 变更日志文件 |

### 完成后下一步

执行 `/1-需求分析` 开始第一个需求的工作流程。
