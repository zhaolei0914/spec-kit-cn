## 阶段 1：自动生成 Skill 文件

根据项目类型执行对应的分析工具：

**Python 项目（Django）**：
```bash
// turbo
python .specify/scripts/python/skill_main.py all . --output .windsurf/skills/project-context
```

**Shell 脚本项目**：
```bash
// turbo
python .specify/scripts/shell/skill_main.py all . --output .windsurf/skills/project-context
```

> 工具会自动分析代码、生成知识库和 Skill 文件到 `.windsurf/skills/project-context/`。

## 阶段 6：更新项目规则

写入前先检测项目实际情况，动态填充 `{{变量}}` 部分：

**检测项：**
- `{{CODE_DIRS}}`：扫描项目根目录，确定代码目录（如 `src/`、`app/`、`lib/` 等），用于触发条件
- `{{SPECS_DIR}}`：确认需求文档目录是否存在（默认 `specs/`），不存在则提示用户是否创建

在 `.windsurfrules` 中写入以下完整内容（覆盖已有内容）：

```markdown
---
## 开发前置（强制）
必须用中文回答
进行代码开发前，**必须**先读取 `.windsurf/skills/project-context/SKILL.md` 和 `.windsurf/skills/project-context/memory/index.md`。

## 代码-文档同步规则（强制）

### 触发条件

本规则**仅适用于计划外变更**：

| 变更场景 | 触发？ | 原因 |
|---|---|---|
| `/6-编写代码` 按 tasks.md 执行 | ❌ 不触发 | 计划内变更，文档已在 `/2`、`/3` 阶段提前编写 |
| Bug 修复（用户报告或测试发现） | ✅ 触发 | 计划外变更，需回溯更新文档 |
| 功能调整（用户临时要求改需求） | ✅ 触发 | 计划外变更 |
| 补充遗漏（实现后发现设计遗漏） | ✅ 触发 | 计划外变更 |
| 纯重构（行为不变） | ❌ 不触发 | 无文档影响 |

**判断标准**：当前是否在执行 `/6-编写代码` 工作流的 tasks.md 任务？是 → 计划内，不触发；否 → 计划外，触发。

### 步骤1：分析变更

- 分析问题原因和影响范围
- **必须**确定关联的需求 ID，按优先级判断：
  1. 用户在对话中明确提及的需求 ID
  2. 代码中的追溯注释（`FR-xxx` / `设计追溯: design.md X.X`）
  3. `specs/` 目录名语义匹配
- 如果无法确定需求 ID → **询问用户**，不可跳过

### 步骤2：执行代码编写

按常规流程修改代码。编写前**必须**读取项目记忆中的编码规范和已知陷阱（参见 SKILL.md 项目记忆章节的读取时机）。

### 步骤3：记录变更日志

代码修改完成后，**必须**在 `.ai-changelogs.md` 的「未同步」章节追加一条记录（读取 `.ai-changelogs.md` 时**只读取「未同步」章节**，避免数据量过大影响性能）：

- **[YYYY-MM-DD HH:MM]** `需求ID`
  - **文件**: `文件路径` → `函数名/改动点`
  - **问题原因**: 简要描述为什么要改
  - **调整方式**: 具体做了什么调整
  - **影响**: FR-xxx, design.md X.X（列出受影响的需求编号和设计章节）

**文件范围**：仅当修改了**代码目录**下的文件时才记录。默认代码目录为 `{{CODE_DIRS}}`；修改文档（`specs/`、`docs/`）、配置（`.windsurf/`、`.specify/`）、记忆（`memory/`）、tasks.md 等非代码文件不触发记录。纯聊天/讨论不记录。

### 步骤4：自动同步文档

记录 changelog 后，**必须**立即执行文档同步：

1. 读取关联需求的 `specs/[ID]/` 下的文档（**必须**包含 requirement.md、spec.md、design.md）
2. 按变更影响范围更新对应章节：
   - **FR 描述变化** → 更新 spec.md 对应 FR + 版本历史
   - **函数签名/参数/流程变化** → 更新 design.md 对应章节
   - **新增业务规则** → spec.md 新增 FR + design.md 新增 BR
   - **异常处理变化** → 更新 design.md 异常处理章节
   - **Bug修复（行为不变）** → 更新 design.md 异常处理（如适用）
   - **纯重构（行为不变）** → 不更新文档
3. 更新文档的版本历史
4. 将 changelog 条目从「未同步」移到「已同步」，补充同步时间和更新内容

### 步骤5：归档检查

检查 `.ai-changelogs.md`「已同步」章节条目数量，超过 30 条时将最早的条目移到「归档」章节。

### 步骤6：记忆更新检查

评估本次修复是否产生了可泛化的经验（需同时满足：可泛化 + 非显而易见 + 可操作）：
- 新编码规范 → 追加 `.windsurf/skills/project-context/memory/coding-standards.md`
- 新项目陷阱 → 追加 `.windsurf/skills/project-context/memory/known-pitfalls.md`

### 步骤7：汇报

告知用户：代码已修改，文档已同步，列出更新了哪些文档的哪些章节。

### 兜底规则

执行 `/5-实施前检测`、`/9-测试验证` 时，**必须**先检查 `.ai-changelogs.md` 是否有「未同步」条目：
- 有 → 先执行文档同步，再继续正式流程
- 无 → 正常执行

### 手动补救

如需全量同步或自动同步遗漏，使用 `/10-同步文档` 工作流手动触发。
```

同时确保 `.ai-changelogs.md` 文件存在，不存在则创建：

-->
