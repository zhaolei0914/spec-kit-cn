## 阶段 1：生成 Skill 文件

### 步骤 1.1：检测项目状态

检测项目是否有代码可供分析：

```bash
# 检测代码目录是否存在且非空
ls -d src/ lib/ app/ main/ 2>/dev/null | head -1
```

**判断结果**：
- **已有代码**（存在代码目录且非空）→ 执行 **步骤 1.2A**
- **新项目**（无代码或空项目）→ 执行 **步骤 1.2B**

---

### 步骤 1.2A：代码分析（已有代码项目）

根据项目类型选择分析工具：

| 项目类型 | 分析工具 | 命令 |
|---------|---------|------|
| Shell 脚本 | 语言专用脚本 | `python .specify/scripts/shell/skill_main.py all . --output __AGENT_SKILLS_DIR__/project-context` |
| Python（Docker可用） | GitNexus | 见下方 GitNexus 流程 |
| Python（Docker不可用） | 语言专用脚本 | `python .specify/scripts/python/skill_main.py all . --output __AGENT_SKILLS_DIR__/project-context` |
| 其他语言 | GitNexus | 见下方 GitNexus 流程 |

**GitNexus 流程**：

```bash
# 步骤 1 — 运行分析
// turbo
bash .specify/scripts/docker/gitnexus/gitnexus.sh analyze --skills .

# 步骤 2 — 转换为 Skill 格式
// turbo
python .specify/scripts/docker/gitnexus/gitnexus_to_skill.py . --output __AGENT_SKILLS_DIR__/project-context
```

> 代码分析会生成 `SKILL.md`（骨架文档）和 `.context-facts.json`（采集事实数据）。

---

### 步骤 1.2B：引导式创建（新项目）

通过问答引导创建 Skill 文件：

**1. 询问用户项目信息**

向用户提问：
- **项目名称**：项目的名称是什么？
- **项目描述**：一句话描述项目目标和用途
- **项目类型**：Web应用 / CLI工具 / 库SDK / 微服务 / 数据处理 / 其他
- **技术栈**：编程语言、框架、数据库、其他依赖
- **核心原则**：项目的开发原则是什么？（可选，参考示例）
  - 示例：库优先、测试优先、CLI接口、可观测性、简单性等

**2. 生成初始文件**

```bash
// turbo
mkdir -p __AGENT_SKILLS_DIR__/project-context src/ specs/archived/ docs/
cp __AGENT_TEMPLATES_DIR__/skill-template.md __AGENT_SKILLS_DIR__/project-context/SKILL.md
echo '{"project_facts": {}, "code_patterns": {}}' > __AGENT_SKILLS_DIR__/project-context/.context-facts.json
[ ! -d .git ] && git init
```

**3. 填充用户信息**

将用户提供的信息填充到 `SKILL.md` 中，保留 `{{LLM_*}}` 占位符。

> 新项目后续可重新运行代码分析来补充更多上下文。

## 阶段 2：LLM 推理填充占位符

### 步骤 2.1：加载数据

1. 读取 `__AGENT_SKILLS_DIR__/project-context/SKILL.md`（骨架文档）
2. 读取 `__AGENT_SKILLS_DIR__/project-context/.context-facts.json`（采集事实数据）
3. **如果存在 `AGENTS.md`** → 补充读取，提取项目描述、设计决策、通用规范等信息

### 步骤 2.2：填充占位符

对每个 `{{LLM_*}}` 占位符：
1. 阅读其下方的 `<!-- 填充指导 -->` 注释
2. 按指导策略推理填充内容
3. 替换占位符为实际内容
4. 删除填充指导注释

**注意**：`_EXTRA` 和 `_DETAIL` 后缀的占位符是可选补充，无内容时直接删除该占位符行。

### 步骤 2.3：处理未填充占位符

对无法填充的占位符（如新项目无代码可分析）：
- 标记为 `TODO(占位符名): 原因说明`
- 保留占位符行，不删除

### 步骤 2.4：版本控制

如果 SKILL.md 已存在：
- 读取现有版本号（文件顶部 `version: X.Y.Z`）
- 根据变更程度递增：
  - **MAJOR**：结构重构（章节重组）
  - **MINOR**：新增章节或大幅扩展
  - **PATCH**：内容更新、澄清
- 新项目版本为 `1.0.0`

在 SKILL.md 顶部添加 frontmatter：
```yaml
---
version: 1.0.0
updated: YYYY-MM-DD
---
```

### 步骤 2.5：质量自检

完成所有填充后，执行以下检查：

1. **占位符清零**：搜索 `{{LLM_`，确认无残留占位符（或已标记 TODO）
2. **注释清理**：搜索 `<!-- 填充指导`，确认无残留注释
3. **事实一致性**：检查填充内容与 `.context-facts.json` 中的事实数据不矛盾
4. **无幻觉**：所有提到的文件路径、类名、函数名必须在代码中实际存在
5. **行数控制**：SKILL.md 应控制在 **300-500 行** 以内；超出则精简冗余信息

### 步骤 2.6：输出摘要

完成后输出：

```
✅ SKILL.md 已更新
版本: v1.0.0 → v1.1.0 (MINOR)
变更章节: 技术栈、架构
TODO 项: 2
  - TODO(LLM_BUSINESS_FLOWS): 无入口函数可分析
  - TODO(LLM_DESIGN_PATTERNS): 无代码可识别模式

建议提交消息: docs: update SKILL.md to v1.1.0 (add architecture section)
```

## 阶段 3：更新项目规则

**步骤 3.1：初始化目录结构**

创建必需的目录结构：

```bash
// turbo
mkdir -p specs/archived/
```

**步骤 3.2：追加 SKILL.md 项目记忆引用**

在 `SKILL.md` 末尾追加以下内容（如已存在「项目记忆」章节则跳过）：

```markdown
## 项目记忆

项目开发记忆独立管理，入口文件：[`.specify/memory/MEMORY.md`](../../../.specify/memory/MEMORY.md)

**开发前必须先读取 `.specify/memory/MEMORY.md` 和 `.specify/memory/index.md`**，然后按 MEMORY.md 中的读取协议按需加载对应记忆文件。
```

**步骤 3.3：检测项目实际情况**

动态填充 `{{变量}}` 部分：
- `{{CODE_DIRS}}`：扫描项目根目录，确定代码目录（如 `src/`、`app/`、`lib/` 等），用于触发条件
- `{{SPECS_DIR}}`：确认需求文档目录是否存在（默认 `specs/`），不存在则提示用户是否创建

**步骤 3.4：确保 AGENT_RULES_FILE 存在**

检查 `__AGENT_RULES_FILE__` 是否存在：
- ❌ 不存在 → **创建空文件**：
  ```bash
  // turbo
  mkdir -p $(dirname __AGENT_RULES_FILE__) && touch __AGENT_RULES_FILE__
  ```
- ✅ 存在 → 继续

**步骤 3.5：读取模板并填充变量**

1. 读取 `__AGENT_TEMPLATES_DIR__/AGENT_RULES_FILE.md` 模板内容
2. 替换模板中的变量占位符：
   - `{{CODE_DIRS}}` → 实际检测到的代码目录（如 `src/`, `lib/` 等）
   - `{{SPECS_DIR}}` → 实际检测到的specs目录（默认 `specs/`）
   - `__AGENT_SKILLS_DIR__` → 实际skills目录路径
   - `__AGENT_CONFIG_DIR__` → 实际config目录路径

**步骤 3.6：追加到 AGENT_RULES_FILE**

将填充后的内容追加到 `__AGENT_RULES_FILE__` 文件末尾（如果内容已存在则跳过，避免重复）。

---

同时确保 `.ai-changelogs.md` 文件存在，不存在则从模板复制：

```bash
// turbo
cp __AGENT_TEMPLATES_DIR__/ai-changelogs.md .ai-changelogs.md
```
