## 阶段 1：生成 Skill 文件

### 步骤 1.1：检测项目状态

检测项目是否有代码可供分析（支持多种项目结构）：

```bash
# 检测代码目录是否存在且非空（扩展支持多种项目类型）
ls -d src/ lib/ app/ main/ cmd/ pkg/ internal/ service/ api/ 2>/dev/null | head -1
```

**目录说明**：
- `src/`, `lib/`, `app/`: Python, JavaScript, TypeScript, Ruby 等
- `main/`, `cmd/`, `pkg/`, `internal/`: Go 项目
- `service/`, `api/`: 微服务架构
- 其他语言特定目录会在后续自动检测

**判断结果**：
- **已有代码**（存在任一代码目录且非空）→ 执行 **步骤 1.2A**
- **新项目**（无代码或空项目）→ 执行 **步骤 1.2B**

---

### 步骤 1.2A：代码分析（已有代码项目）

根据项目类型选择分析工具：

| 项目类型 | 分析工具 | 命令 |
|---------|---------|------|
| Shell 脚本 | 语言专用脚本 | `python .specify/scripts/shell/skill_main.py all . --output .windsurf/skills/project-context` |
| Python / 其他语言 | GitNexus MCP | 见下方 GitNexus MCP 流程 |

**GitNexus MCP 流程**：

使用 MCP gitnexus 工具进行代码分析：

**步骤 1：检查远程仓库**

```bash
// turbo
git remote get-url origin
```

- ✅ 有远程仓库 → 继续步骤 2
- ❌ 无远程仓库 → **停止**，提示用户：
  ```

  GitNexus 需要远程 Git 仓库 URL 才能进行分析。

  请选择以下方案之一：
  1. 推送代码到远程仓库后重新运行此命令
  2. 使用语言专用脚本进行本地分析
  ```

**步骤 2：调用 GitNexus 分析**

使用 `mcp2_get_or_analyze` 工具：
- **输入参数**：
  - `repo_url`: Git 仓库 URL（从步骤 1 获取）

- **返回值**（**必须保存到变量**）：
  ```bash
  # 调用 MCP 工具并保存返回值
  RESULT=$(调用 mcp2_get_or_analyze)

  # 从返回值中提取项目名称（必须保存，后续步骤会用到）
  PROJECT_NAME=$(从 RESULT 中提取 project_name)
  ```

- **返回值字段**：
  - `project_name`: 项目名称（**必须保存到 $PROJECT_NAME 变量**）
  - `skill_path`: SKILL.md 文件路径
  - `wiki_path`: Wiki 目录路径
  - `status`: 分析状态

- **失败检测与处理**：

  检查返回值的 `status` 字段：

  ```bash
  if [ "$status" != "success" ]; then
    # 失败 → 执行失败处理协议
  fi
  ```

  **如果失败，必须按失败处理协议报告**：

  ```markdown
  ## ❌ 执行失败

  **失败阶段**: 阶段 1 - 生成 Skill 文件
  **失败步骤**: 步骤 1.2A.2 - GitNexus 代码分析
  **错误信息**:
  \`\`\`
  [mcp2_get_or_analyze 返回的完整错误信息]
  \`\`\`

  **失败原因分析**:
  GitNexus 分析失败，可能原因：
  - GitNexus 服务未启动或无法访问
  - 仓库 URL 格式不正确
  - 仓库需要认证但未配置凭据
  - 网络连接问题

  **可能的解决方案**:

  1. **检查 GitNexus 服务状态** (推荐)
     - **操作步骤**:
       1. 检查服务是否运行：`curl http://10.4.51.215:8001/health`
       2. 如未运行，启动服务：`npx gitnexus serve`
     - **适用场景**: GitNexus 服务未启动
     - **风险**: 无

  2. **验证仓库 URL**
     - **操作步骤**:
       1. 检查 URL：`git remote get-url origin`
       2. 确认 URL 格式正确（https:// 或 git@）
       3. 测试访问：`git ls-remote origin`
     - **适用场景**: 仓库 URL 配置错误
     - **风险**: 无

  3. **使用本地分析（降级方案）**
     - **操作步骤**:
       1. 检测项目语言
       2. 使用语言专用脚本进行本地分析
     - **适用场景**: GitNexus 服务不可用且无法修复
     - **风险**: 分析结果可能不如 GitNexus 完整

  **需要你的决策**:
  - [ ] 选择方案 1 - 检查服务状态
  - [ ] 选择方案 2 - 验证仓库 URL
  - [ ] 选择方案 3 - 使用本地分析
  - [ ] 提供其他解决方案
  - [ ] 需要更多信息（请描述）

  **恢复指令**:
  解决问题后，重新运行此命令即可从失败点继续。
  ```

  **等待用户响应后再继续。**

**步骤 3：下载完整上下文文件**

使用 `.specify/scripts/fetch_context.py` 脚本下载文件：

```bash
// turbo
# 获取 GitNexus 服务地址（从环境变量或使用默认值）
GITNEXUS_SERVER=${GITNEXUS_SERVER:-"http://10.4.51.215:8001"}

# 使用步骤 2 中保存的 PROJECT_NAME 变量
# 使用 fetch_context.py 下载文档
python3 .specify/scripts/fetch_context.py "$PROJECT_NAME" --server "$GITNEXUS_SERVER"
```

- **说明**：
  - 使用步骤 2 中保存的 `$PROJECT_NAME` 变量
  - 脚本会自动下载 SKILL.md 和 Wiki 文档到 `.specify/` 目录

- **失败检测与处理**：

  检查脚本执行结果：

  ```bash
  if [ $? -ne 0 ]; then
    # 失败 → 执行失败处理协议
  fi
  ```

  **如果失败，必须按失败处理协议报告**，提供以下解决方案：

  1. **检查 GitNexus 服务连接**
     - 操作：`curl $GITNEXUS_SERVER/health`
     - 适用：服务地址配置错误或服务未运行

  2. **验证项目已索引**
     - 操作：检查项目是否在 GitNexus 中
     - 适用：项目未被 GitNexus 分析

  3. **检查网络连接**
     - 操作：测试网络连接
     - 适用：网络问题导致无法下载

  **等待用户响应后再继续。**

**步骤 4：输出分析摘要**

显示分析结果：

```

✅ GitNexus 代码分析完成

项目名称: {project_name}
SKILL.md: .windsurf/skills/project-context/SKILL.md
Wiki 文档: .specify/wikis/ (如果存在)

📝 生成的文件：
  - SKILL.md: 项目技能描述文档
  - wikis/*.md: 中文 Wiki 文档（如果存在）

💡 提示：
  - 如需更新分析结果，重新运行此命令即可
  - Wiki 文档位于 .specify/wikis/，可供参考
```

> **设计说明**：
> - GitNexus 生成的 SKILL.md 复制到项目 skills 目录
> - Wiki 文档保留在 `.specify/wikis/` 目录供参考
> - `.specify/wikis/` 目录应添加到 `.gitignore`，不纳入版本控制
> - 临时下载的 `.specify/skills/` 目录会在复制后自动删除
> - 所有错误都会停止流程，由用户决定下一步操作
