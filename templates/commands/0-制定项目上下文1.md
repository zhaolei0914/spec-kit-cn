### 步骤 1.1：检测项目状态

检测项目是否有代码可供分析（支持多种项目结构）：

```bash

```

**目录说明**：
- `src/`, `lib/`, `app/`: Python, JavaScript, TypeScript, Ruby 等
- `main/`, `cmd/`, `pkg/`, `internal/`: Go 项目

- 其他语言特定目录会在后续自动检测

**判断结果**：

**GitNexus MCP 流程**：

**步骤 1：检查远程仓库**

  - `project_name`: 项目名称（**必须保存到 $PROJECT_NAME 变量**）
  - `skill_path`: SKILL.md 文件路径

## 阶段 4：Git 历史记忆提取

**步骤 4.1：检测 Git 仓库并获取提交历史**

检查当前项目是否为 Git 仓库：

```bash
// turbo
if ! git rev-parse --git-dir > /dev/null 2>&1; then
    echo "⚠️  非 Git 仓库，跳过历史记忆提取"
    exit 0
fi

echo "🔍 检测到 Git 仓库，开始提取历史记忆..."
echo ""

# 获取最近 100 个提交
git log -n 100 --pretty=format:"%H|%an|%ad|%s" --date=short > /tmp/git_all_commits.txt

# 统计总数
TOTAL_COMMITS=$(wc -l < /tmp/git_all_commits.txt)

if [ "$TOTAL_COMMITS" -eq 0 ]; then
    echo "⚠️  未找到提交历史，跳过记忆提取"
    exit 0
fi

echo "📊 分析范围: 最近 $TOTAL_COMMITS 个提交"
echo "🔄 开始智能分类..."
echo ""
```

---

**步骤 4.2：LLM 智能分类提交**

**对每批 10 个 commits 调用 LLM 进行分类**：

**LLM 分类 Prompt**：

```
你是一个 Git 提交历史分析专家。请分析以下 Git 提交，判断每个提交的类型和是否值得提取到项目记忆中。

**提交列表**：
{commit_hash} | {author} | {date} | {message}
{commit_hash} | {author} | {date} | {message}
...（最多 10 个）

**分类标准**：
- **coding_standard**: 编码规范变更（命名、格式、导入、错误处理等）
- **design_decision**: 设计决策（新功能、重构、架构变更）
- **bug_fix**: Bug 修复（修复错误、解决问题）
- **other**: 其他（文档更新、配置调整、依赖升级等）

**判断依据**：
- 看 commit message 的关键词和描述
- 推断提交的意图和影响范围
- 评估是否有长期记忆价值

**输出 JSON 格式**：
[
  {
    "commit_hash": "abc123",
    "category": "coding_standard|design_decision|bug_fix|other",
    "worth_extracting": true/false,
    "reason": "简短说明"
  },
  ...
]

**注意**：
- 只有真正有价值的提交才标记 worth_extracting=true
- 简单的文档更新、依赖升级、格式调整等不值得提取
- 如果 commit message 太简短（如"update"、"fix"），标记为 other 且 worth_extracting=false
```

**批量处理**：
- 每批 10 个 commits
- 并发调用 LLM（3-5 并发）
- 显示进度：`🔄 分类中... (15/30)`

**筛选结果**：

```bash
# 从分类结果中筛选出值得提取的 commits，按类别分组
STYLE_COMMITS=$(筛选 category=coding_standard 且 worth_extracting=true)
DESIGN_COMMITS=$(筛选 category=design_decision 且 worth_extracting=true)
FIX_COMMITS=$(筛选 category=bug_fix 且 worth_extracting=true)

echo "✅ 智能分类完成！"
echo ""
echo "📊 分类结果："
echo "  - 编码规范相关: ${#STYLE_COMMITS[@]} 个"
echo "  - 设计决策相关: ${#DESIGN_COMMITS[@]} 个"
echo "  - Bug 修复相关: ${#FIX_COMMITS[@]} 个"
echo "  - 总计候选: $((${#STYLE_COMMITS[@]} + ${#DESIGN_COMMITS[@]} + ${#FIX_COMMITS[@]})) 个"
```

---

**判断**：
- 如果总候选数 == 0 → 提示"未找到有价值的提交"，跳过步骤 4.3
- 如果总候选数 > 0 → 继续步骤 4.3

### 第二阶段：LLM 深度分析（精准提取）

**步骤 4.3：逐个分析候选 commits**

**分析模板**（以编码规范为例）：

```
分析以下 Git Commit，判断是否包含编码规范变更：

**Commit Hash**: {commit_hash}
```
