## 任务格式

```text
- [ ] [任务编号] [并行?] [故事?] 带文件路径的描述 | 验收标准 | FR-xxx
```

**格式组件**:
1. **复选框**: 始终以 `- [ ]` 开头
2. **任务编号**: T001、T002、T003...
3. **[并行]**: 可并行执行时添加（不同文件、无依赖）
4. **[故事N]**: 用户故事阶段的任务必须有（如 [故事1]、[故事2]）
5. **描述**: 带确切文件路径的清晰操作
6. **验收标准**: 可验证的完成条件（必须）
7. **设计追溯**: FR-xxx/NFR-xxx 编号（功能任务必须）

### 测试方法与技术规范

**测试框架**（从 SKILL.md 技术栈提取）:
- Python: `pytest` + `pytest-cov`
- JavaScript/TypeScript: `jest` / `vitest`
- Go: `go test`
- Shell: `bats` / `shunit2`

**测试类型与方法**:

| 层级 | 测试类型 | 测试方法 | 覆盖要求 |
|------|----------|----------|----------|
| **数据层** | 单元测试 | 模型字段验证、约束检查、方法测试 | 正常值/边界值/异常值 |
| **逻辑层** | 单元测试 | 业务规则验证、异常处理、Mock依赖 | 正向流程/逆向流程/边界条件 |
| **接口层** | 接口测试 | HTTP请求测试/CLI参数测试 | 正常参数/边界参数/异常参数 |
| **集成** | 端到端测试 | 完整业务流程验证 | 主要流程/备选流程/异常流程 |

**测试用例结构**:
```python
def test_[场景]_[操作]_[预期结果]():
    """
    测试用例: [用例标题]
    前置条件: [环境/数据/状态要求]
    操作步骤: [明确的操作序列]
    预期结果: [具体可验证的结果]
    """
    # Arrange - 准备测试数据
    # Act - 执行被测试操作
    # Assert - 验证结果
```

**覆盖场景清单**:
- ✅ 正常流程: 有效输入 → 预期输出
- ✅ 边界值: 最小值/最大值/空值/特殊字符
- ✅ 异常场景: 无效输入/缺失参数/权限不足
- ✅ 错误处理: 错误码正确/错误信息清晰

## 任务完成标准

任务标记为 `[x]` 完成前，必须满足以下条件：

### 代码实现要求

1. **文件存在**: 任务描述中的文件已创建
2. **功能完整**: 业务逻辑完整实现（非占位/TODO）
3. **规范符合**: 代码符合 project.md 中的实现规范
4. **设计追溯**: 代码注释中标注对应的 FR-xxx

### 验收标准要求

每个任务必须包含可验证的完成标准：

| 任务类型 | 验收标准示例 |
|----------|----------------|
| 模型创建 | 模型有 verbose_name、db_table，继承 BaseModel |
| 服务实现 | 有参数校验、权限校验、业务规则校验 |
| API 接口 | 使用统一响应格式，有异常处理 |
| 错误码 | 符合 `服务名.模块.错误` 格式，有完整元数据 |
| 测试用例 | 覆盖正常/异常/边界场景，测试通过 |

### 设计追溯要求

每个任务必须关联对应的设计需求：

```python

    """
```
